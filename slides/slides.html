Background & Protocol Mechanics Speaker 1: Phạm Hữu Đan (20120450)

Why IP + User-Agent Allowlists Break — and What Web Bot Auth Changes

Baseline: User-Agent + IPv4 CIDR Allowlist

  • User-Agent is an unauthenticated plain-text header trivial to spoof.
  • AI agents & crawlers run on shared cloud egress CIDRs (AWS, GCP, Workers).
  • Any co-hosted tenant in 203.0.113.0/24 inherits trusted-bot access.

Change: RFC 9421 + IETF Web Bot Auth (Oct 2026 Draft -01)

  • Bot signs per-request components with private Ed25519 key.
  • Signature-Agent Dictionary header points to HTTPS JWKS directory.
  • Origin verifies signature, (URL, keyid) binding, window & nonce.

Why Request Coalescing Matters on Cold Start (Appendix C.3)

  • At the start of every run, 16 concurrent sockets arrive against an empty JWKS cache.
  • Without coalescing, all 16 requests would trigger redundant HTTPS directory fetches (a self-inflicted burst).
  • With in-flight promise coalescing (DirectoryResolver), exactly 1 directory fetch occurs per run and the remaining 299 valid bot requests hit local RAM cache in ~0.22 ms; end-to-end HTTPS p95 rises from 4.600 ms to 6.043 ms (+1.794 ms median delta).

Two Subtle Costs Highlighted by Our Measurements

  • CPU Asymmetry: Bitmask CIDR lookup takes nanoseconds; parsing Structured Fields + computing RFC 9421 base + Ed25519 curve verification adds 127.0 µs of main-thread active CPU per request across the mixed workload.
  • HPACK / QPACK Incompressibility (Appendix C.7): Because per-request signatures change on every URL and nonce, HTTP/2 and HTTP/3 header tables cannot index the Signature value — literal bytes are paid on every request.

Critical Evaluation · Criterion 3 Speaker 3: Trần Đại Hiệp (23120256)

When NOT to Use Web Bot Auth Directly at Your Origin

1. Unthrottled L7 DDoS / Static Assets

Attackers sending garbage Ed25519 signatures force your origin to spend ~0.22 ms CPU per hit before rejecting. For public static assets or high-RPS origins, verify at an edge CDN proxy or mint a session token after request #1 (§5.6, §6.2).

2. Instant Key Revocation Requirements

The protocol defines zero revocation mechanism (§5.5.2, §6.3). If a bot's private key leaks, stolen signatures verify until expires or until every verifier's cached JWKS max-age TTL expires.

3. Privacy-Sensitive Personal Agents

Signature-Agent URLs identify the signer across origins even across key rotations (§7.1). Never attach a user-specific Signature-Agent URL to personal browsing agents.

4. Without SSRF Guards on Key Discovery

Clients control Signature-Agent. Fetching arbitrary URLs without blocking private IPs (169.254.169.254, 127.0.0.1), redirects, and oversized payloads turns bot auth into an SSRF vulnerability (§6.7).

All 4 limits grounded in draft-ietf-webbotauth-httpsig-protocol-01 Sections 5.6, 6.2, 6.3, 6.7 & 7.1 Slide 8 / 10
Threats to Validity & Engineering Checks Speaker 3: Trần Đại Hiệp (23120256)

Limits of Our Measurement & How We Checked Our Assistant

Limits of Our Measurement

  • Loopback vs. WAN Discovery: Cold JWKS fetch was 2.822 ms on 127.0.0.1; cross-region TLS + DNS adds 50–250 ms on cache miss.
  • Single-Process Nonce Map: Multi-node origins need Redis for atomic replay checks, adding ~0.3–1.5 ms network RTT.
  • GET + Ed25519 Only: rsa-pss-sha512 costs more CPU, and POST bodies require RFC 9530 Content-Digest buffering.

3 Real Bugs Caught & Logged in AI-LOG.md

  • Draft Evolution: Caught outdated bare-string Signature-Agent; updated to Oct 2026 WG Draft -01 Structured Dictionary.
  • Windows 15.625 ms CPU Tick Quantization: process.cpuUsage() gave noisy [0%..118%] jumps; switched to isolated-worker eventLoopUtilization() (IQR 9.7%).
  • Cross-Path Replay: Enforced @method + @path + @query instead of @authority-only signing.
