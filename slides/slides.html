02 Motivation & Wire Protocol
Speaker 1 · Phạm Hữu Đan (20120450)

Why IP + User-Agent Allowlists Break — and What Web Bot Auth Signs

Baseline Failure Mode

User-Agent + Static IPv4 CIDR Allowlist

  • User-Agent is plain text — trivial for any scraper to copy.
  • Modern AI agents & crawlers run on shared cloud egress subnets (AWS, GCP, Cloudflare Workers).
  • Every co-hosted tenant inside 203.0.113.0/24 inherits trusted crawler privileges.
Single Change Under Study

RFC 9421 + IETF Web Bot Auth (29 Oct 2026 WG Draft -01)

  • Bot signs each request with its private Ed25519 key.
  • Dictionary Signature-Agent points to HTTPS /.well-known/http-message-signatures-directory.
  • Origin verifies signature, (URL, keyid) binding, window & nonce.

Two Engineering Costs Exposed by Our Benchmark

  • Main-Thread CPU Asymmetry: 32-bit CIDR bitmask checks take nanoseconds; Structured Field parsing + RFC 9421 base serialization + Ed25519 curve math adds 127.0 µs of active CPU per request across the mixed workload.
  • HPACK / QPACK Header Incompressibility (Appendix C.7): Because per-request signatures change with every URL and nonce, HTTP/2 and HTTP/3 dynamic header tables cannot index Signature — literal bytes are transmitted every time.

08 Critical Evaluation · Criterion 3
Speaker 3 · Trần Đại Hiệp (23120256)

When NOT to Use Web Bot Auth Directly at Your Origin

Case 01 · §5.6 & §6.2

Unthrottled L7 DDoS or Public Static Assets

Attackers flooding invalid Ed25519 signatures force your origin to burn ~0.22 ms CPU per hit before rejecting. Offload verification to an edge CDN proxy or issue a session token after request #1.

Case 02 · §5.5.2 & §6.3

Instant Key Revocation Requirements

Web Bot Auth defines zero revocation channel. If a bot's signing key is compromised, forged signatures remain valid until expires or until every verifier's cached JWKS max-age TTL lapses.

Case 03 · §7.1 Privacy

Privacy-Sensitive Personal Agents

A Signature-Agent URL links requests across origins even after key rotation. Never attach user-identifying Signature-Agent directories to personal user-owned browsing agents.

Case 04 · §6.7 SSRF Surface

Without Strict SSRF Bounds on Key Discovery

Untrusted clients control Signature-Agent. Resolving URLs without blocking private/metadata IPs (169.254.169.254, 127.0.0.1), redirects, and oversized JWKS turns auth into an SSRF vector.

Grounded directly in draft-ietf-webbotauth-httpsig-protocol-01 Sections 5.6, 6.2, 6.3, 6.7 & 7.1 Slide 08 / 10
09 Threats to Validity & Verification
Speaker 3 · Trần Đại Hiệp (23120256)

Limits of Our Measurement & Defects Caught in AI-LOG.md

Measurement Boundaries

What Would Change in Production

  • Loopback vs. WAN Discovery: Cold JWKS fetch took 2.822 ms over 127.0.0.1; cross-region DNS + TLS adds 50–250 ms on cache miss.
  • In-Memory Nonce Store: Multi-replica origins require a shared Redis store for atomic replay checks, adding ~0.3–1.5 ms RTT.
  • GET + Ed25519 Scope: rsa-pss-sha512 costs higher CPU, and POST bodies require RFC 9530 Content-Digest buffering.
Criterion 6 · AI Verification

Real Technical Defects Caught & Fixed

  • Oct 2026 Draft Evolution: Caught superseded bare-string Signature-Agent; implemented WG Draft -01 Structured Dictionary.
  • Windows 15.625 ms CPU Tick Noise: process.cpuUsage() quantized to 1/64 s ticks ([0%..118%]); replaced with isolated-worker eventLoopUtilization() (IQR 9.7%).
  • Cross-Path Replay & Stale Tooling: Enforced @method + @path + @query and upgraded deprecated ESLint 9 / Actions v4 to ESLint 10 & v7.
