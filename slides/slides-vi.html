Vì sao IP + User-Agent thất bại — và Web Bot Auth ký những gì?

Điểm mù của Baseline

Kiểm tra User-Agent + dải IPv4 CIDR tĩnh

  • User-Agent là chuỗi văn bản trần — mọi công cụ cào dữ liệu đều giả mạo được.
  • Các AI crawler & agent hiện chạy trên hạ tầng cloud dùng chung dải IP (AWS, GCP, Cloudflare Workers).
  • Mọi tenant thuê chung subnet 203.0.113.0/24 đều nghiễm nhiên vượt qua IP allowlist.
Điểm thay đổi duy nhất (Change)

RFC 9421 + IETF Web Bot Auth (Bản nháp WG -01, 29/10/2026)

  • Bot ký số từng request bằng khóa bí mật bất đối xứng Ed25519.
  • Header Signature-Agent kiểu Dictionary trỏ tới HTTPS /.well-known/http-message-signatures-directory.
  • Origin đối chiếu chữ ký, cặp khóa (URL, keyid), thời hạn & nonce.

Hai chi phí kỹ thuật quan trọng rút ra từ thực nghiệm

  • Độ chênh lệch CPU trên luồng chính: Phép so bitmask CIDR chỉ mất vài nano-giây; trong khi phân tích Structured Fields + dựng chuỗi cơ sở RFC 9421 + kiểm tra đường cong Ed25519 tiêu tốn thêm 127.0 µs CPU hoạt động mỗi request.
  • Không nén được bằng bảng tĩnh HPACK / QPACK (Phụ lục C.7): Do chữ ký thay đổi theo từng đường dẫn và nonce, HTTP/2 và HTTP/3 không thể tái sử dụng chỉ mục cho giá trị Signature — phải truyền nguyên bytes mỗi lần.

4 trường hợp KHÔNG NÊN bật Web Bot Auth trực tiếp tại Origin

Trường hợp 01 · §5.6 & §6.2

Tài nguyên tĩnh công khai hoặc đang chịu L7 DDoS

Kẻ tấn công bắn ồ ạt chữ ký Ed25519 rác sẽ ép Origin tốn ~0.22 ms CPU mỗi request trước khi từ chối. Hãy đẩy bước xác thực ra CDN Edge Proxy hoặc cấp session token ngắn sau request #1.

Trường hợp 02 · §5.5.2 & §6.3

Nghiệp vụ đòi hỏi thu hồi khóa tức thì (Instant Revocation)

Giao thức không có kênh thu hồi khóa. Nếu lộ khóa bí mật của bot, chữ ký giả mạo vẫn tiếp tục hợp lệ cho tới khi hết expires hoặc hết hạn max-age của cache JWKS tại các server.

Trường hợp 03 · §7.1 Quyền riêng tư

Agent cá nhân cần ẩn danh giữa các Website

URL trong Signature-Agent làm lộ danh tính xuyên tên miền ngay cả khi đã xoay vòng khóa mới. Tuyệt đối không gắn URL định danh cá nhân cho trình duyệt agent của người dùng cuối.

Trường hợp 04 · §6.7 Bề mặt SSRF

Chưa triển khai bộ lọc chống SSRF khi tải khóa

Client tự truyền URL Signature-Agent. Nếu server tải thẳng mà không chặn IP nội bộ/metadata (169.254.169.254, 127.0.0.1), tắt redirect và giới hạn dung lượng JWKS sẽ mở ra lỗ hổng SSRF.

Giới hạn của phép đo

Điều gì sẽ thay đổi trên môi trường Production?

  • Loopback so với mạng WAN: Tải JWKS lạnh trên 127.0.0.1 chỉ mất 2.822 ms; qua mạng liên lục địa (DNS + TLS) sẽ tốn 50–250 ms mỗi lần lệch cache.
  • Bộ nhớ Nonce cục bộ: Cụm nhiều server Origin cần Redis để chống phát lại nguyên tử, cộng thêm ~0.3–1.5 ms RTT mạng nội bộ.
  • Phạm vi GET + Ed25519: Thuật toán rsa-pss-sha512 tốn CPU hơn, và POST cần băm body qua RFC 9530 Content-Digest.
